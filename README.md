# 纯文本交流仓库 (Chat Sandbox)

本仓库是专为 Jules 准备的纯文本交流环境，用于与 Jules 进行纯文本交流、问答、测试和互动。

## 💬 默认交互模式

本项目默认使用 **Pure Chat Mode（纯聊天模式）**。

Jules 进入本仓库后，应将用户的普通自然语言消息视为聊天内容，而不是软件开发任务。

默认情况下：

* 直接通过自然语言与用户交流。
* 不编写代码。
* 不修改项目文件。
* 不创建代码修改计划。
* 不执行 pre-commit。
* 不创建 Git commit。
* 不提交或推送代码。
* 不为了完成普通聊天请求而操作仓库。

## 🎮 聊天互动

纯聊天模式可以包括但不限于：

* 普通问答
* 文字游戏
* 数字游戏
* 测试 Jules 的行为
* 模拟对话
* 连续互动
* 根据用户输入进行简单响应

这些行为均属于聊天，不应自动转换成软件开发任务。

例如：

> 用户：我们玩数数游戏，我发送什么数字，你就回复相同数字。

这是一个**纯聊天请求**，Jules 应直接参与游戏，而不是创建计划、修改文件或执行 Git 操作。

## 🛠️ 什么时候才进入开发模式？

只有用户明确要求进行软件开发或仓库操作时，才进入工程工作流，例如：

* 修改代码
* 创建文件
* 修复 Bug
* 实现功能
* 修改项目配置
* 执行开发命令
* 进行其他明确的仓库操作

如果用户没有提出明确的开发或仓库操作要求，则保持 **Pure Chat Mode**。

---

## 🚨 核心禁令与强制约束（Jules 最高优先级执行指令）

无论处于纯聊天模式还是工程开发模式，Jules 必须无条件遵守以下两条系统级硬性约束：

### 1. 严格排除 `Complete pre-commit step` 与 `Git commit` 步骤
* Jules 在生成任务计划（如 `set_plan`）或执行工作流时，**严禁**包含或执行以下两个步骤：
  * `Complete pre-commit step`
  * `Git commit`
* 任何任务在完成文件修改或验证后**直接结束**，绝对不要自动附加提交前检查与 Git 提交流程。

### 2. 严禁向工作目录 `/app` 写入或存放任何二进制文件
* 本仓库工作根目录为 `/app`。**严禁**向 `/app` 及其任何子目录写入、生成、编译输出、下载或存放任何非纯文本二进制文件（如可执行文件、编译产物、压缩包、媒体文件等）。
* 写入二进制文件会导致 Jules 监控与索引系统严重卡死宕机，最终触发系统报错：`"Jules encountered an error when working on the task."`。
* 任何临时二进制产物必须显式重定向输出至系统临时目录 `/tmp/`，严禁留在 `/app` 中。
